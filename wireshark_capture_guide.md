# Wireshark Packet Capture & Inspection Guide for CSL-I11 (mTLS)

This guide provides step-by-step instructions for capturing and analyzing Mutual TLS (mTLS) packets in Wireshark for **Chapter 5 (Results & Testing)** of your mini-project report.

---

### Step 1: Open Wireshark and Select Interface
1. Launch **Wireshark**.
2. Select the interface handling local socket traffic:
   * **On Windows:** Double-click **`Adapter for loopback traffic capture`** (or `Npcap Loopback Adapter`).
   * **On Linux:** Double-click **`lo`** (Loopback Interface).

---

### Step 2: Apply Display Filter
In the top Wireshark filter bar, enter:
```wireshark
tcp.port == 8443 && tls
```
or simply:
```wireshark
tls
```
Press **Enter**. The packet list will start filtering TLS protocol packets.

---

### Step 3: Trigger the Handshake
Open a terminal in the project directory and run:
```bash
python iot_device.py device01
```

---

### Step 4: Key Packets to Inspect and Screenshot for Report

#### Packet 1: Client Hello
* Expand **`Transport Layer Security`** -> **`TLSv1.3 Record Layer: Handshake Protocol: Client Hello`**.
* Look at **`Cipher Suites`**: Shows the encryption algorithms supported by the IoT device.
* Look at **`Extension: supported_versions`**: Confirms TLS 1.3 support.

#### Packet 2: Server Hello & Certificate Request
* Expand **`Handshake Protocol: Server Hello`**.
* In standard TLS, the server only sends `Certificate`.
* **In mTLS**, expand and highlight **`Handshake Protocol: Certificate Request`**.
* This frame proves the server is enforcing **Mutual Authentication** by requiring the IoT client to provide its certificate!

#### Packet 3: Client Certificate & Certificate Verify
* Expand **`Handshake Protocol: Certificate`**: Shows `device01` sending its X.509 public certificate to the gateway.
* Expand **`Handshake Protocol: Certificate Verify`**: Shows the **Digital Signature** generated by the client private key over the handshake transcript.
* This fulfills **RTU Syllabus Exp 8 (Digital Signature)**.

#### Packet 4: Application Data
* Expand **`TLSv1.3 Record Layer: Application Data Protocol: Hypertext Transfer Protocol / Encrypted Data`**.
* Notice: The sensor payload (JSON temperature, humidity, voltage) is completely encrypted. An eavesdropper sniffing the Wi-Fi or LAN cannot read the data.

---

### Step 5: Wireshark Capture for Negative Tests (Rogue Attack)
1. Keep Wireshark running with the `tls` filter.
2. In your terminal, run:
```bash
python rogue_device.py
```
3. In Wireshark, observe:
   * **`Alert (Level: Fatal, Description: Bad Certificate / Certificate Unknown / Handshake Failure)`**.
   * Take a screenshot of this alert message to prove the defense mechanisms in Section 5.3 of your report.
